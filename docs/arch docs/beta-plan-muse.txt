Music Director Runner — план доработки до внутренней беты
========================================================
Автор: muse-spark | Дата: 2026-08-28 | Источник: status.md HANDOFF, architecture.md, update1-design/plan, destroy-update, about v2.txt

Цель беты
---------
Внутренняя бета, не публичная. Десктоп браузер (Chrome/Firefox).
Критерий: посторонний без подсказок запускает, играет 5 мин, понимает цель,
чувствует разницу car/horse/rocket, хочет рестарт. Кубы заменены на покупной low-poly.
Мобайл, мета-прогрессия, скины, лидерборд — вне беты.

Принцип эффективности
---------------------
80% ощущения беты = 20% работ: арт-свап + нормальный флоу + уборка топ-фрикций.
Новая геймплей-механика в бете — стоп. Тюнинг только числами в json.
Порядок фаз критичен: визуал -> UX -> сок -> техдолг -> баланс.
Делать сок/баланс на кубах — пустая трата.

Фаза 0 — Заморозка скоупа (1 день)
----------------------------------
0.1 Зафиксировать что входит: car/horse/rocket + Destroy дефолт, 1 трек за забег,
    4 полосы, нитро, рампы, поезда, Director как есть.
0.2 Зафиксировать что НЕ входит: мобайл, сохранения прогрессии, магазин, онлайн,
    редактор треков, новые типы препятствий.
0.3 Definition of Done беты: билд запускается с демо-треком без выбора файла,
    60 fps на среднем ноуте, нет софтлоков на 5 тестовых треках.

Фаза 1 — Арт-свап (~40% времени, максимальный визуальный скачок)
----------------------------------------------------------------
1.1 Пайплайн: папка assets/, загрузка glb/gltf, один лоадер в GameScene.
     Размеры хитбоксов не менять — модели подогнать под obstacleFootprint
     (low 1.2x2.32, tall 1.5x8.0, micro 0.4x0.9).
1.2 Персонажи: машина (куб->машина), конь (шар->конь/мото), ракета (пирамида->ракета).
     Один пак low-poly, 3 модели + 2 вариации цвета под режимы.
1.3 Препятствия/мир: low/tall/micro, монета, рампа, поезд, дорога, небо.
     Свет/туман перенастроить под новые материалы, шейдеры не трогать.
1.4 Проверка: визуальная читаемость — тип препятствия ясен за 0.3с на скорости 15.

Фаза 2 — Скелет UX (убирает 90% фрикций)
----------------------------------------
2.1 Флоу экранов: Меню -> Выбор файла -> Игра -> Пауза (Esc) -> Результаты -> Рестарт.
     Сейчас всё в bootstrap/HUD — разнести по src/ui/screens/.
2.2 Загрузка трека: drag&drop + кнопка, прогресс, ошибки формата, демо-трек по дефолту
     (чтобы бета запускалась без действий).
2.3 HUD: убрать debug, оставить только NITRO/ADREN/MOMENTUM + очки + дистанция.
     Адаптировать под новые модели (не перекрывает персонажа).
2.4 Настройки: громкость, выбор пресета gen/adren, сохранение в localStorage.
     Hot-reload конфигов оставить для разработки.

Фаза 3 — Обучение и сок (без новых механик)
--------------------------------------------
3.1 Туториал 30 сек на первом забеге: полосы -> нитро (стрелка вверх) -> рампа ->
     поезд -> конь (прыжок/подкат). Оверлей стрелок, не текст-стена. Скип по Esc.
3.2 Звук/камера/VFX: ребаланс под новые модели — громкость хитов, shake, FOV,
     фрагменты. Логика уже есть, только числа.
3.3 Читаемость смерти: понятно почему умер (tall vs low), 2с блок рестарта уже есть,
     добавить подсказку на Game Over.

Фаза 4 — Техдолг и перфоманс
-----------------------------
4.1 Билд: vite build -> статика в dist/, проверка на чистом профиле браузера.
4.2 Производительность: лимит фрагментов (120), тени/постпроцессинг, 60 fps цель.
     Профилировка GameLoop fixedUpdate 60Hz.
4.3 Кросс-браузер/аудио: автовоспроизведение через GainNode (не muted), фолбек
     ворклета, обработка ended трека (fade уже есть).
4.4 Стабильность: прогон 5 треков разных жанров (EDM/рок/эмбиент/речь/тишина)
     без непроходимых ситуаций — проверка isPassable тестами + ручной прогон.

Фаза 5 — Баланс-петля (только после Фазы 1)
-------------------------------------------
5.1 Закрытый плейтест 5-7 человек с логированием (PlaytestRecorder уже есть).
     Сбор .playtest.json + report.md.
5.2 2 итерации тюнинга только числами: game.default.json / levelgen.default.json
     (плотность, нитро, интервалы коня/ракеты). Без кода.
5.3 Финальная приёмка по DoD Фазы 0. Решение: бета принята или ещё итерация.

Что не делать в бете
--------------------
- Не добавлять новые режимы/способности.
- Не переписывать Director/LevelGenerator логику — только пресеты.
- Не делать мобайл-инпут (свайпы) — отложить.
- Не полировать шейдеры/постпроцессинг до плейтеста Фазы 5.

Оценка порядка работ
--------------------
0 (1д) -> 1 (1-2 недели, зависит от выбора пака) -> 2 (1 неделя) -> 3 (3-5 дней) ->
4 (3-5 дней) -> 5 (1 неделя с паузами на фидбек). Итого 4-6 недель соло.
